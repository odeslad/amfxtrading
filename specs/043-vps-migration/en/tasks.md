# 043 — VPS migration · Tasks

Each task is one conventional commit. Tasks that are operations on the servers change no source file: their commit is the `verification.md` entry with the evidence (`docs(specs):`). Tasks of different layers never share a commit. The old system stays in production at `v2.amfxtrading.com` until task 14. **Execution order** (changed after task 4, when the `v2` name was dropped — see the design): 1–4 → tunnel (8) → repo changes committed locally (9–12) → database rehearsal, terminals, startup (5–7, with the changed scripts copied to the new VPS) → joint push of 9–12, which verifies them → port 22 and runbook (13) → switch (14) → documentation (15) → validation and observation (16) → closure (17).
